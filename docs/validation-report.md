# 공개 내용 정리 검증

## 2026-11-13 포트폴리오 공유 추가

하단의 이력서 링크를 '포트폴리오 공유'로 교체하고 `/portfolio/`에 한 페이지 요약을 추가했다. 활성 공개 페이지는 24개다. 요약에는 기존 공개 데이터의 소개, 기술, 업무 프로젝트 6개와 개인 제작 2개, 전공·자격을 사용한다. 로컬 MVP와 음악동아리 관리 기능의 제한도 유지한다.

- 공유 창은 현재 보고 있는 페이지와 관계없이 공개 요약 주소를 표시한다. 링크 복사, 기기 공유, 텔레그램 공유와 요약 미리보기를 제공한다.
- 클립보드 접근을 사용할 수 없으면 URL을 선택하고 직접 복사 방법을 안내한다. 기기 공유의 취소와 실패를 구분하며 메시지가 발송됐다고 표시하지 않는다.
- `node --test tests/site.test.mjs tests/share.test.mjs`: 17개 통과. 기존 링크·공개 범위·날짜 검사와 함께 모든 하단 링크의 공유 대상, 요약의 프로젝트·범위 보존, 복사 성공·거부, 공유 성공·취소·미지원·실패 처리를 검사했다. 구문 검사와 `git diff --check`도 통과했다.
- 브라우저에서 요약 페이지를 320·375·1037px로 확인했다. 가로 넘침이 없고, 업무 6개·개인 2개와 제목 하나를 유지한다. 320px 공유 창의 링크와 버튼이 화면 안에 배치되고 Escape로 닫힌다. 기존 전체 검색의 GitLab 검색도 동작하며 브라우저 오류 로그는 없었다.
- 앱 미리보기와 Chrome에서 복사 API의 완료 안내를 확인했다. 자동화 도구의 별도 클립보드에서는 OS 클립보드 값을 읽을 수 없어 실제 붙여넣기 결과는 확인하지 못했다. 두 환경에서 기기 공유 창 호출이 실패해 링크 복사 안내가 표시되는 것을 확인했다. OS별 공유 앱 선택 화면과 메시지 발송은 검증하지 않았다.

기기 공유는 [W3C Web Share](https://www.w3.org/TR/web-share/), 복사는 [Clipboard.writeText](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText), 텔레그램 링크는 [공식 공유 위젯](https://core.telegram.org/widgets/share)의 동작을 따른다. 별도 메신저 키나 외부 분석 스크립트를 추가하지 않았다.

## 2026-11-13 흰색 버전 배포 전 점검

기존 흰색 프로젝트 탐색 디자인에 최신 공개 콘텐츠를 반영했다. 업무 프로젝트 6개와 개인 프로젝트 2개, 경력 10건, 업무 기록 9편이며 활성 페이지는 23개다. 2025년 12월–2026년 1월 기술 지원과 2026년 7월 운송 시뮬레이션 이력을 추가했다. 근거 메일과 식별 정보는 저장소에 포함하지 않는다.

- 프로젝트·경력·업무 기록을 확인된 날짜 기준 최신순으로 생성한다. 연도만 있는 항목에는 월을 추가하지 않는다.
- 업무 상세 9개에 개별 '한 줄 요약'을 표시하고 검색 색인에도 반영한다.
- 경력증명서 기재 기간과 이후 업무 메일로 확인한 참여 이력을 구분한다. 구축안은 설치 완료로, 시뮬레이션 결과는 실제 운영 성과로 표현하지 않는다.
- 음악동아리의 로그인·저장·업로드 비활성화 상태를 상세에 유지한다. 랩타일링크의 성장 기록·일정 기능은 저장소 구현 기록과 대조했다.
- 좁은 화면에서 경력표의 글자가 잘게 끊겨 보이던 부분을 개선했다. 모바일에서는 각 행을 프로젝트명·참여 기간·분야·직급으로 묶어 보여주며 PC와 인쇄에서는 표를 유지한다.
- 고객사 식별 명칭과 원본 경력 자료를 공개 코드·문서·생성 페이지에 포함하지 않았는지 점검했다.
- 상단의 중복 직무 표기를 제거하고, 소개·이력서의 자기소개를 해온 일·협업과 소통 방식·앞으로의 방향을 담은 세 문단으로 수정했다. 320px와 1037px에서 글과 검색 버튼이 화면을 넘지 않고 정상 배치되는지 확인했다.

`node --test tests/site.test.mjs`: 11개 통과. 내부 링크·앵커, 개인정보 관련 공개 필드, 검색·sitemap, 이전 생성물 정리, HTML 이스케이프, 최신순 정렬, 기간의 정밀도와 공개용 canonical·Open Graph 주소를 확인했다. 모든 활성 페이지의 localhost·테스트 표기·검색 제외 태그가 없는지 검사했다. 코드 구문 검사와 `git diff --check`도 통과했다.

실제 브라우저에서 23개 페이지를 320px로 점검했고 가로 넘침·제목 누락·도식 글자 잘림이 없었다. 홈은 375·768·1280px에서도 확인했다. 모바일 표 개선 후 경력·이력서·소개·개인 프로젝트 상세 2개를 다시 확인했다. 개인 분류 2개, Vite 검색 1개, 검색 결과 없음, 전체 8개 복귀, 프로젝트 선택과 상세 이동, GitLab 전체 검색, Escape 닫기, 모바일 메뉴의 경력 이동이 동작했다. 브라우저 오류 로그는 없었다.

생성된 이력서 HTML과 인쇄 스타일은 검사했으며 새 PDF는 만들지 않았다. 프로젝트 서비스의 로그인 이후 기능과 JavaScript를 끈 브라우저의 직접 실행은 이번 배포 검증에 포함하지 않았다.

## 검증

`node --test tests/site.test.mjs`: 7개 통과. 랩타일링크의 제작 내용과 서비스 링크가 생성되고 소개·이력서에도 표시되는지 회귀 검사를 추가했다.

내부 링크·앵커, 공개 필드, 검색·sitemap의 대상, 제외된 원본·이미지 경로, 삭제한 기록의 생성 페이지 잔존 방지와 HTML 출력을 확인했다. 변경 코드 구문 검사와 공백 검사도 통과했다.

현재 공개 파일과 경로에서 정리 대상 고유명·개인 식별 항목이 남지 않았는지 별도 점검했다. 검사는 Git 이력과 로컬 의존성 캐시를 제외한 현재 파일에 대한 것이다.

Chrome에서 홈을 1280px, 768px, 375px, 320px로 확인했다. 가로 넘침이 없었고, 업무·개인 분류, 기술명 검색, 검색 결과 없음, 선택 프로젝트 요약과 전체 검색이 동작했다. 모바일 메뉴와 Escape로 검색 닫기도 확인했다.

가독성 수정 후 랩타일링크 상세, 소개, 경력과 이력서를 1280px와 320px에서 확인했다. 가로 넘침이 없었고 각 페이지의 h1은 하나였다. 브라우저의 오류 로그는 없었다. 홈은 1280px, 768px, 375px, 320px에서 확인했고 기본 본문 크기는 16px, 프로젝트 제목은 14–15px, 보조 표기는 13px이었다. 개인 분류에서 2개, Vite 검색에서 랩타일링크 1개가 표시됐다. 내부 링크와 앵커는 활성 공개 문서 19개, 제외 안내와 404를 포함해 자동 검사했다.

문자 파비콘을 데이터베이스 픽토그램으로 교체했다. CSS와 파비콘 주소에 변경 버전을 붙여 이전 파일의 브라우저 캐시를 피한다. 랩타일링크의 공개 홈은 확인했으며 로그인 후 저장·권한 동작은 이번 작업의 검증 대상에 포함하지 않았다.

이번 수정에서는 인쇄용 HTML과 인쇄 스타일을 갱신했으며 새 PDF를 생성하거나 인쇄 결과의 페이지 수를 검증하지 않았다. JavaScript 비활성화 브라우저 검증은 재실행하지 않았다. 각 프로젝트의 실제 상세 링크는 정적 HTML에 유지하고 자동 검사했다.

## 범위

공개 파일에 대한 점검이며 원격 저장소의 과거 이력은 변경하지 않는다. 원본 증빙과 비공개 근거 자료는 공개 저장소 밖에서 보존한다. 배포 결과는 GitHub Pages와 실제 공개 URL에서 별도로 확인한다.
